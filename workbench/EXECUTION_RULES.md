# 執行鐵律：分模組開發、驗收與部署

本文件是本專案後續修改的強制工作規範。任何模組、整合或部署工作均須遵守。

1. **先盤點，再動手**：先比對各分支、版本、備份及既有測試成果，確認最完整、正確的基準版本；不得憑檔名或版本號猜測。
2. **分頭完成**：將功能拆成獨立模組，能先完成的先完成，不讓單一困難項目阻塞其他工作。
3. **各模組先獨立驗收**：每個模組先檢查功能、計算、版面及列印；不合格不得進入整合。
4. **保留原始成果**：不得直接破壞正式版本；每次修改均須有可回復的分支或備份。
5. **統一整合**：模組通過驗收後再整合成完整網站，並保留手機容易上傳的單一 `index.html` 及完整 ZIP 部署包。
6. **最難項目最後攻克**：先完成可獨立處理的項目，避免所有工作被單一難題拖住。
7. **整合後完整回歸測試**：模組單獨通過不代表整站通過；整合後仍須測試各功能及相互影響。
8. **列印規格不得自行簡化**：依已確認的區塊、A4 直式、分頁及各試算獨立列印要求驗收。
9. **卡關立即換路徑**：遭限流、權限阻擋或工具失敗時，先判斷根因，停止重複無效操作，改用可行替代方法。
10. **完成才算完成**：程式提交、檔案產生、測試通過、正式部署是不同階段，必須分別如實回報，不得混為一談。
11. **先交付可測試成果**：能先完成的項目先交付，不以長篇計畫取代實際成果。
12. **未驗收不部署**：正式網站維持不動，直到整合、回歸測試及部署包檢查完成；正式部署另依明確授權執行。

## 驗收門檻

- 模組來源與基準版本可追溯。
- 模組抽取或修改有差異紀錄。
- 自動語法檢查通過。
- 計算測試案例與既有已確認結果逐筆比對。
- 個別列印及整份文件列印均完成 A4 預覽與版面驗收。
- 整合後全站回歸測試通過。
- 單檔 HTML 與 ZIP 內容完整，所有相依資產均包含。
- 部署前明確標示版本、部署目標與回復方式。

任何一項未完成，狀態只能標示為「進行中」或「未驗收」，不得標示為正式完成。
