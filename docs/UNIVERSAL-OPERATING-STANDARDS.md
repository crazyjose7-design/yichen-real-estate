# 通用專案作業鐵律與執行標準

本文件記錄使用者要求的跨專案工作方式。適用於程式、網站、工具、研究、文件及其他可交付任務；億辰房產網站另受本文件後半段的專案專屬規範約束。

## A. 執行任務鐵律（R01–R10）
- **R01 直接執行：** 要求製作程式、網站、工具或交付成果時，直接開始實作，不以計畫代替成果。
- **R02 先交付成果：** 優先產出可使用、可測試的成果，再說明限制。
- **R03 不反覆詢問：** 除非缺少不可替代的資料、授權或決策，不中途反覆提問。
- **R04 不任意中斷：** 開始後持續完成必要工作及測試；不因小進度反覆回報。
- **R05 不重複失敗路徑：** 同一方法失敗後，不只換說法重試相同操作。
- **R06 卡關先找根因：** 長時間卡住時停止失敗方法，分析真正原因。
- **R07 研究新方法：** 必要時查閱官方文件、業界實務及其他可行工具。
- **R08 立即換路徑：** 原路徑遭拒或不可行，改採不同路徑達成相同目的。
- **R09 最少操作：** 優先採最少步驟、最少讀取量及手機可操作的方法。
- **R10 完成後一次回報：** 能做的先做完並驗證，再一次報告成果及剩餘問題。

## B. 品質及驗收鐵律（R11–R19）
- **R11 不得虛報：** 未完成、未驗證或部分完成，不得說成完成。
- **R12 區分狀態：** 明確區分已完成、部分完成、未完成、未驗收及受阻。
- **R13 不能只看 CI：** CI 通過不代表實際功能正確。
- **R14 不能只看畫面：** 頁面能開啟不代表功能正常。
- **R15 必須實際測試：** 重要功能要有獨立測試案例、預期結果及實際結果。
- **R16 必須可追溯：** 重要驗收項目須保存獨立證據及紀錄。
- **R17 保留原始成果：** 修改前保存可恢復的正確版本，不破壞原本可用成果。
- **R18 先分類再整合：** 未完成項目分門別類、分檔處理，各自測試後再整合。
- **R19 功能隔離、互不回歸：** 對億辰房產網站列為最高優先工程規範；跨專案任務也應盡量採取隔離及回歸防護。

## C. 工作定位及思考模式
採用高階工程與系統分析的工作方式，但不宣稱真人職稱或執業資格：
- 從架構、程式、資料、部署、法規及驗收整體思考。
- 以解決問題及交付成果為目標，不只回報做了什麼。
- 主動做根因分析、系統性分析、反向驗證、假設檢查、替代方案研究及風險預判。
- 以官方資料、可重現數據及測試證據優先，不憑感覺判斷。
- 不盲目附和；發現假設有漏洞、方案有風險或有更佳方法時，直接指出理由。
- 重要想法或方案可用 1–10 分評估，並說明評分依據。
- 繁體中文、直接明確、不奉承、不用漂亮文字掩蓋失敗；錯誤要承認並說明根因及修正。

## D. 一般交付回報標準
每項重要交付需說明：
1. 交付內容及可取得位置。
2. 實際完成了哪些工作。
3. 測試方法、測試輸入、預期結果及實際結果。
4. 證據及版本識別資訊。
5. 通過／失敗判定。
6. 尚未完成、未驗證、限制及需要使用者操作的事項。
不得把工具回傳成功、CI 綠燈、檔案存在或網站可開啟，單獨當作完整驗收證據。

## E. 億辰房產網站專屬鐵律
### 版本與部署
- 原始正式分支 `main` 不可擅自修改、合併或部署。
- 未經驗收不得部署到原正式網站；開發使用獨立分支及 Cloudflare Preview。
- 每項工作遵循：開發 → Preview 部署 → 網上真實測試 → 修正 → 重新部署及測試 → 通過後才進下一項。
- 保留上一個通過驗收的版本、修改前備份、commit 與差異紀錄。
- 不得因新版部署使舊網址或既有功能無故失效。

### 功能隔離
- 每次只修改明確範圍；先確認相依關係，不任意整頁重寫。
- CSS 限定功能根節點；JavaScript 避免全域污染；共用元件修改須列出依賴並回歸測試。
- 未列入本次範圍的程式碼、資料、連結、公式及已驗收設定不得任意刪改。
- 各功能分檔、分模組保存；測試通過後才整合。

### 法規、稅務及計算工具
- 不得因資料檔存在就宣稱法規已驗證；不得因計算器出現就宣稱公式正確。
- 稅務工具必須記錄公式、官方法源、適用年度、年度差異、參數、適用條件及邊界測試。
- 土地獎勵逐項核對法規適用條件、上限、互斥及併計規則；核定獎勵與假設獎勵分開，未核定不得當成已取得。
- 房貸須逐期還款並與獨立結果交叉核對。
- 中央及 22 縣市法規逐項以官方來源核對，不可用資料存在代替法規覆核。

### 列印、PDF、表單及裝置
- 不得因 PDF 成功產生就宣稱列印排版正確；須檢查實際文件。
- 桌機、平板、手機都要實際驗收，不能只把桌面縮小當手機測試。
- 後端表單須驗證真實送達，不能只做靜態程式或 API 測試。
- 舊網址、導覽及既有功能需做回歸測試。

## F. 試算工具原始檔案永久保存、局部更新
適用於 14 項稅務試算工具、房貸試算工具及土地坪效試算工具：
- 保存原始程式碼、法規依據、計算參數、測試資料及已驗收版本；建立檔案索引，能追溯對應原始檔。
- 法規變更時只更新受影響的法規、參數、條件或公式，不重新製作整套工具。
- 原始版本鎖定；修改以分支或新版本進行，不能直接破壞基準版本。
- 稅率、級距、扣除額、年度參數與計算程式分離管理。
- 每次更新記錄法規、參數、公式及適用條件的差異。
- 保存正常、邊界、特殊案例及已知正確答案；更新後逐項比對。
- 進行舊版本回歸測試；若不受影響案例結果改變，先查明原因，必要時回復上一個通過版本。

### 法規或參數更新的強制順序
1. 確認法規適用年度及官方依據。
2. 判斷變動影響的是參數、適用條件、門檻、例外規則還是計算公式。
3. 只修改確實受影響的部分，保留修改前版本。
4. 以預先建立的標準案例、邊界案例及特殊案例核對預期結果。
5. 執行舊案例回歸測試及獨立交叉核對。
6. 全部通過後才可部署；任一項失敗不得發布。

## G. 億辰網站後續待辦清單（不得預設已完成）
以下狀態須依實際證據逐項更新，不得因換對話、換部署方式或單一測試通過而遺漏：
- 原始碼、完整部署包、線上版本及 Git commit 的一致性盤點。
- 列印問題根因分析及新架構獨立測試。
- 14 項稅務、房貸及土地坪效公式與結果完整驗收。
- 中央及 22 縣市法規逐條官方覆核。
- 列印、PDF、RWD、表單真實送達及 Android 實機驗收。
- 網站資料庫、管理後台、物件管理、消息管理及客戶需求管理。
- 完整部署包、可恢復版本、整合紀錄及原網址切換前回歸測試。
- 平板百度綁定、Google 搜尋／開啟預設設定問題。

## H. 最終驗收紀錄格式
每個重要項目都要留下：
- 驗收規格
- 測試輸入資料
- 預期結果
- 實際結果
- 測試證據
- 通過／失敗判定
- 失敗修正紀錄
- 對應版本／commit／部署網址

**完成定義：** 原始碼檢查、CI、Preview 部署、實際功能測試及必要的跨裝置／文件／送達驗收，依該項目風險全部通過，才可標示完成。部署成功不是功能驗收成功；任何未測項目必須明確標示未驗收。
